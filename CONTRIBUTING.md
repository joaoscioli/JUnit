# Contributing

This repository is maintained as a Java testing lab.

## Working Style

- Add focused examples that teach one testing idea at a time.
- Prefer readable tests over clever test code.
- Name tests by behavior and expected outcome.
- Document the boundary between unit, integration, and contract tests.

## Before Opening A Pull Request

- Run the test suite.
- Check whether the example improves the testing guide.
- Keep fixtures and test data easy to understand.

## Review Focus

Reviewers should look for clarity, deterministic behavior, useful assertions,
and maintainable test structure.
