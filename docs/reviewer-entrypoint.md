# Reviewer Entrypoint

Use this page when you have only a few minutes to evaluate the repository.

## First Three Files

- `README.md` for the project purpose and navigation.
- `docs/technical-scope.md` for what the project proves today.
- `docs/test-style-guide.md` for practical testing conventions.

## What To Look For

- Tests organized around behavior rather than implementation trivia.
- Naming and fixture choices that make failures easy to diagnose.
- Clear boundaries between unit tests, mocks, and integration concerns.

## Strong Interview Signal

The repository is strongest when discussed as a testing maturity example: it
shows how tests protect behavior, document edge cases, and support refactoring.
