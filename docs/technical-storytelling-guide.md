# Technical Storytelling Guide

Use this guide to present the project clearly in an interview.

## Story Arc

1. Start with the problem: teams need confidence to change Java code safely.
2. Explain the testing boundary: unit tests protect rules, integration tests
   protect wiring, and mocks belong around external dependencies.
3. Defend the quality signal: coverage helps, but behavior, edge cases, and
   useful failures matter more.
4. Close with maintainability: tests should explain the system and survive
   refactoring.

## Strong Closing

This project is designed to show how I use tests as engineering documentation
and regression protection.
