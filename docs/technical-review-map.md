# Technical Review Map

Use this map to review the repository quickly without losing the technical story.

## Review Path

1. Start with `docs/technical-elevator-pitch.md` for the short positioning.
2. Read `docs/test-style-guide.md` for test-writing conventions.
3. Open `docs/technical-risks.md` for testing pitfalls.
4. Check `docs/acceptance-criteria.md` for the next behavior-focused test slice.
5. Finish with `docs/seniority-evidence.md` to connect the project to interview
   signal.

## Reviewer Takeaway

The project should be evaluated as evidence of test-design maturity: tests should
communicate behavior, expose risk, and make refactoring safer.
