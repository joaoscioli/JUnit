# Senior Demo Path

Use this repository to show testing judgment, not only JUnit syntax.

## 1. Test behavior

Start with examples that describe business behavior in readable names and clear assertions.

## 2. Separate test levels

Explain which cases are unit tests, which would become integration tests, and which should stay out of the test suite because they are framework concerns.

## 3. Show maintainability

Point to test data builders, parameterized tests, dynamic tests, and assertion strategy as evidence that the suite can grow without becoming noisy.

## 4. Discuss risk

A strong interview answer connects tests to risk: money movement, authentication, validation, edge cases, and regression protection.
