# Demo Evaluation Rubric

Use this rubric to evaluate a technical walkthrough of this project.

| Area | Strong Signal | Weak Signal |
| --- | --- | --- |
| Test intent | Explains the behavior each test protects. | Talks mostly about coverage percentage. |
| Boundaries | Separates unit, integration, and external dependency tests. | Mocks everything by default. |
| Maintainability | Uses clear names, fixtures, and focused assertions. | Couples tests tightly to implementation details. |
| Failure value | Describes what a failing test teaches the team. | Treats test failures as noise. |

## Passing Bar

A strong demo proves that testing decisions support refactoring confidence and
business-rule protection.
